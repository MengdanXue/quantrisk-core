## 0. 结论摘要

1. 审计报告里的 7 条前视记录涉及 **4 只股票**，原因有两类，不是 3 条：
   - **600030、601012**：真实的配股，数据中没有记录，属于真实的前视排除，已改为按时点判定；
   - **600309、603501**：是数据质量检查的误报。分红除息日恰好落在停牌期间，因子跳变到复牌首日才出现，被误判为“未记录事件”。分红记录本身正确，误报已修复。
2. 修复后，Walk-Forward 默认按时点判定数据可用性：事件之前照常参与选股；从事件当日收盘起不可用，直到信号回看窗口不再覆盖事件。
3. M3 全部研究已重新运行：均线交叉 Walk-Forward、横截面两类因子的 Walk-Forward、78 组试验矩阵、DSR、PBO、审计。另外做了知悉滞后 1 天的敏感性分析和一项归因诊断。
4. **研究结论没有实质变化**：

## 1. 逐条核查

### 1.1 事件日期的口径

- [数据] 后复权因子表（`stock_zh_a_daily(adjust="hfq-factor")`）中，因子发生变化的日期，就是价格实际出现除权缺口的交易日。
  - 600030、601012：这个日期与新浪配股记录中的“除权日”一致（见 1.2）。
  - 600309、603501：除息日停牌，因子变化出现在复牌首日（见 1.3）。
- 结论：因子表里的日期是**生效日**，或者生效之后的第一个交易日；**不是公告日**。
- 公告日只出现在为了核实而另外查询的配股记录里。修复规则**不使用公告日**。

### 1.3 600309 与 603501：停牌期间分红造成的误报

| 项目 | 600309 万华化学 | 603501 韦尔股份 |
|---|---|---|
| 停牌（快照中无行情） | 2017-12-05 至 2018-06-01 | 2018-05-15 至 2018-09-11 |
| 分红除息日（巨潮、新浪两个来源一致） | 2018-01-26，每股 1.5 元 | 2018-08-10，每股 0.045 元 |
| 因子跳变日（复牌首日） | 2018-06-04，比例 1.041164 | 2018-09-12，比例 1.001195 |
| 按停牌前收盘价推算的比例 | 37.94/(37.94−1.5) = 1.041164 | 37.70/(37.70−0.045) = 1.001195 |
| 新浪配股记录 | 无 | 无 |

- [代码] 原来的检查把除息日不在行情中的记录标为 `EX_DATE_NOT_TRADED`（不算问题），但复牌首日的因子跳变找不到同日记录，于是被判为 `UNRECORDED_ADJUSTMENT`。
- [运行] 核对后，回测引擎本身对这两只股票的处理是对的：现金分红在除息日入账，信号复权在复牌首日按停牌前收盘价计算。只是数据质量检查误报，导致它们在 2018–2020 年的若干段和试验矩阵里被整段排除。

## 2. 修复方法

| 改动 | 位置 | 说明 |
|---|---|---|
| 停牌期间分红的核对 | [代码] `ashare.py:371-403` | 除息日停牌时，到复牌首日核对因子跳变：与停牌前收盘价推算的结果一致，就标为 `VERIFIED_BY_FACTOR_NEXT_TRADED_DAY`，该日不再判为未记录事件；不一致则仍然报警（有测试覆盖） |
| 带日期的问题事件 | [代码] `ashare.py:253`、`:270-283`、`:311` | 未记录的公司行为、来源冲突、公告晚于除权日、价格超出涨跌停、数据中断，各自记录发生日期，存入 `quality["issue_events"]` |
| 按时点判定可用性 | [代码] `ashare.py:316` `point_in_time_usable` | 事件 e 之前：可用。从 e 之后第 `knowledge_lag_days` 个交易日的收盘起不可用，直到 e 之后满 `contamination_days` 个交易日；数据中断之后一直不可用 |
| Walk-Forward 接入 | [代码] `walk_forward.py:165-166`、`:214-231`、`:233-240`、`:115` | 新增 `quality_mode="point_in_time"`（默认），污染窗口等于 `warmup_days`（研究中最长的信号回看期）。股票池资格改为“股票池资格 ∧ 当日数据可用”。`quality_mode="whole_segment"` 保留修复前的做法，只用于复现对比 |
| 横截面研究接入 | [代码] `cross_section.py` 中的 `run_cross_section`、`CrossSectionStudy.run_segment` | 使用同一按时点股票池；放行的数据集记录在 `data_quality_overrides` 中 |

**原有检查全部保留，没有删除任何过滤条件：**

- `quality["usable"]` 和 `quality["issues"]` 的整段语义不变；组合入口 `run_strategy_portfolio` 默认仍然拒绝不可用的数据（`test_unrecorded_adjustment_makes_data_unusable_and_backtest_refuses` 照常通过）；
- 停牌：没有行情时订单作废；价格异常：涨跌停检查；数据缺失：行情日期不在交易日历中、重复日期仍然直接报错；
- 只有 Walk-Forward 的按时点路径，会把**仅含带日期问题**的数据集放进回测，并且只在不可用的日子里禁止参与。

**不可用期间股票怎么处理**（[代码] `daily.py:494-497`，引擎未修改）：

- 不可用当天收盘，持仓生成 `UNIVERSE_EXIT` 卖单，下一交易日开盘撮合；不可用期间不买入。
- 事件发生时如果仍然持有（例如在停牌中）：引擎没有配股记录，按“不参与配股”处理，除权缺口计为亏损。[推断] 对不认购配股的投资者来说，这是真实的经济损失，因为 A 股配股权不能交易；但现实中投资者可以选择认购，这一点没有建模。

**没有改动的内容**：M0/M1 的核心交易逻辑（`daily.py`、`ledger.py`、`execution.py`、`base.py`、`ashare_rules.py`）、风险约束、自动减仓开关（仍关闭）、历史原始数据（快照文件哈希不变，加载时会校验）、研究参数。

## 3. 时间口径的可验证性

| 问题 | 结论 |
|---|---|
| 因子表日期是公告日、生效日还是其他 | **可验证**：是除权（息）生效日，停牌时为生效后的第一个交易日。依据：600030、601012 与配股记录的除权日一致，按配股公式推算的价格与因子吻合到小数点后 3 位；600309、603501 与分红记录的除息日对应 |
| 除权日当天收盘时，市场是否已经知道这个事件 | **部分可验证**：价格缺口当天就出现在日线行情里（[数据] 600030 前收盘 25.70，01-27 开盘 24.81；601012 前收盘 27.09，开盘 22.50）。但“当天收盘时数据源能不能拿到当天的后复权因子”，**不可验证** |
| 公告日（早 8–10 个交易日）时信息是否已公开 | **不可验证**：配股记录是 2026 年查询的结果，无法证明这些记录当时就能获取。**因此规则不使用公告日**，只使用价格实际跳变的日期 |

针对“当天收盘时是否已知”无法验证的问题，做了**敏感性分析**：假设事件晚 1 个交易日才被知悉（`--knowledge-lag 1`），结果见 5.4，结论不变。

- [推断] 两者在 2019–2021 年是持续性很强的上涨股，动量配置会稳定选中它们，使得样本内外的排名一致。
- 在一个只有 13–33 只股票、且有幸存者偏差的股票池里，PBO 会被一两只股票左右，所以**它不能作为策略稳健的证据**。
